# 技术五：权限控制与多租户隔离

## 技术定位

该技术用于保证集团统一平台下，不同基地、不同部门、不同岗位在同一系统中安全协同。

## 为什么采用

- 3 个生产基地共享一套平台
- 总部与基地的管理视角不同
- 工单、设备、分析数据都存在权限边界
- 企业级系统必须具备可审计能力

## 在项目中的具体场景

### 场景 1：基地数据隔离

基地运维人员默认仅可查看本基地设备、告警和工单数据。

### 场景 2：集团总部统一监管

总部管理者可按授权查看跨基地汇总数据和关键指标。

### 场景 3：角色驱动功能控制

设备管理员、运维工程师、基地负责人拥有不同菜单和操作权限。

## 决策要点

- 功能权限和数据权限分开设计
- 组织架构与角色体系结合使用
- 敏感操作必须记录审计日志
- 跨域访问采用显式授权而非默认放开

## 项目贴合场景示例

在本项目中，权限体系不是简单的账号管理，而是“总部、基地、车间、岗位”多层级管控。

典型链路可写为：

`用户登录 -> SSO/认证中心(Keycloak) -> JWT Token -> Gateway 鉴权 -> 业务服务按 RBAC + 数据域过滤`

项目贴合场景可以写成：

- 总部设备管理人员可查看 3 个基地汇总看板
- 基地运维工程师只能查看本基地设备、告警和工单
- 车间班组长可查看本车间工单和处理记录
- 敏感操作如规则变更、强制关闭工单必须写审计日志

## 可写入论文主体内容

在集团统一平台建设中，我把权限控制和多租户隔离作为一项基础架构能力来设计，而不是等业务完成后再补充。原因在于，平台同时服务总部和3个生产基地，不同角色在功能使用范围和数据可见范围上都有明显差异，如果缺少清晰的边界控制，平台越成功推广，管理风险反而越大。基于这一认识，我设计了以组织架构为基础、以 `OAuth 2.0/OIDC + JWT` 为认证基础、以 `RBAC` 为核心、以数据域隔离为补充的复合权限模型。具体而言，用户首先通过统一认证中心完成登录，再由 `Gateway` 和业务服务基于 Token、角色和基地域进行访问控制；在功能上按角色分配菜单与操作权限，在数据上按基地和设备域实施过滤，并通过审计日志记录关键行为。这样既满足总部统一监管需求，又保证基地侧有边界地自治运行，实现了共享平台之上的安全协同。

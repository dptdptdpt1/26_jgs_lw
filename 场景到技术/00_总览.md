# 场景到技术总览

项目固定背景统一参考 [项目固定背景.md](/Users/duanpeitong/Desktop/work/study/26_jgs_lw/项目固定背景.md)。

## 目录定位

本目录用于从项目真实业务场景出发，梳理：

- 场景为什么会出现
- 架构上为什么这样设计
- 落到了哪些关键技术
- 这些内容如何写进论文正文

## 每个场景文件建议回答的问题

1. 这个场景的业务背景是什么
2. 这个场景的核心问题是什么
3. 作为架构师，为什么选择当前方案
4. 这个场景落到了哪些关键技术
5. 这些技术在项目里如何协同
6. 最终带来了什么效果

## 编写约束

- 优先写架构层、平台层、中间件层、协议层和部署层内容
- 尽量不要落到具体编程语言，如 `Java`、`Python`、`Go`
- 如需写具体实现，优先写协议、组件、平台和架构模式，如 `OPC UA`、`Kafka`、`Nginx`、`Gateway`
- 重点始终是“场景 -> 决策 -> 技术 -> 效果”，而不是代码实现细节

## 适用价值

- 看到题目先想到项目场景
- 从场景中反推可用技术点
- 为论文主体内容提供真实业务语境
